# ASMlab 0.1.0 검증 보고서

작성일: 2026-09-22. 대상: 동봉된 Linux x86-64 실행 파일 `bin/asmlab`.

## 결론과 빌드 출처

**14,410개 검사 항목을 실행했고 실패는 0건이었다.** 이 결과는 동봉 실행 파일의 동작 검증 결과이다. **NASM 자체를 사용한 빌드 성공을 확인한 결과는 아니다.**

제작 환경에 NASM이 없었고 패키지 및 소스 다운로드도 실패했다. 따라서 `tools/validation_bridge.py`로 이 프로젝트에서 사용하는 NASM 문법 부분집합을 GNU assembler의 Intel 문법으로 변환하고, GNU `as --64`로 어셈블한 뒤 GCC 링커 드라이버로 libc와 연결했다. 변환기는 지시문, 매크로, 로컬 레이블, 상수 표기와 피연산자 문법을 바꾸는 개발 도구이며 런타임 수학 엔진이 아니다.

제공 소스는 NASM `.asm/.inc`이고, 기본 Makefile은 NASM을 직접 호출한다. 원격 GitHub Actions도 NASM 빌드를 수행하도록 구성했지만 이번 전달 과정에서 원격 실행하지 않았다. NASM의 소스 수용 여부, 부동소수점 상수 인코딩, 생성 결과의 동일성은 네이티브 빌드 후 별도 확인해야 한다. GNU assembler 검증 경로를 NASM 검증으로 대체해 주장하지 않는다.

## 수치 차이와 허용 기준

기준은 Python 표준 라이브러리 `math` 및 직접 계산한 스칼라 공식이다. MPFR 기반의 고정밀 참값 비교나 모든 float64 비트패턴의 전수검사는 아니다.

| 함수 | 관측한 최대 절대 차이 | 테스트의 허용 기준 |
|---|---:|---|
| sin | 1.1102230246251565e-16 | 절대 차이 3e-14 이하 |
| cos | 1.1102230246251565e-16 | 절대 차이 3e-14 이하 |
| log | 1.1368683772161603e-13 | 절대 차이 3e-13 이하 |
| sqrt | 테스트 표본에서는 0 | 상대 차이 1e-15 이하, 0은 정확 비교 |

행렬 곱 테스트의 작은 정수 입력은 float64로 정확하게 표현되는 범위에 있어 차이가 0이었다. 이것을 임의의 실수 행렬에 대해 모든 라이브러리와 비트 단위로 일치한다는 뜻으로 해석하면 안 된다. 전체 오차·테스트 입력 기록은 [verification.json](../evidence/verification.json)에, 알고리즘과 정의역은 [NUMERICS.md](NUMERICS.md)에 있다.

## 실제 실행 기록인지 확인한 방법

`sqrt([1,4,9,16])+2`에서 `sqrtpd` 두 번과 `addpd` 두 번을 확인했다. 각 프레임의 실제 목적 레지스터 결과는 순서대로 `[1,2]`, `[3,4]`, `[3,4]`, `[5,6]`이다. 표시된 16진수 비트가 해당 binary64 표현과 일치하는지 검사했다.

프레임에 보관된 명령 주소를 `objdump -d -Mintel` 결과와 대조하여 해당 주소가 표시된 SSE2 명령을 가리키는지 확인했다. 결과는 같은 수식을 Python으로 계산하여 화면에 덧씌운 값이 아니라 실행 중 메모리에 캡처한 XMM 값이다.

다만 이 검사는 모든 CPU 명령을 추적한다는 의미는 아니다. 선택한 산술·이동·부호 변경 명령만 캡처하며, AST 순회와 분기·모든 메모리 접근 등은 추적하지 않는다. 재생은 계산 완료 후 캡처를 탐색하는 것이며, 디버거의 실시간 명령 단위 실행이나 JIT 컴파일은 아니다.

## 바이너리 의존성과 기본 감사

`readelf`, `nm`, `objdump`로 다음을 확인했다.

- 공유 라이브러리 NEEDED 항목은 `libc.so.6` 하나이다. 외부 `libm`, BLAS, LAPACK 및 Python 런타임에 링크하지 않았다.
- 미해결 동적 심볼에 외부 `sin/cos/sqrt/log/pow/exp` 및 지정한 BLAS·Python 진입점이 없었다.
- GNU_STACK은 실행 권한이 없는 RW였다. 링크 설정은 RELRO 및 즉시 바인딩을 사용한다.
- 실제 실행 파일에 `mulpd`와 `sqrtpd` 명령이 존재했다.

[감사 로그](../evidence/runtime-audit.txt)는 독립적인 보안 인증이 아니다. 이 프로그램은 로컬 단일 사용자용 연구·교육 MVP이며, 신뢰할 수 없는 네트워크 요청을 받는 계산 서버로 검증하지 않았다. 고정 주소 관찰을 위해 non-PIE로 링크했다.

## 재현 명령

동봉 바이너리 자체를 검사한다.

```sh
python3 tests/verify.py bin/asmlab --report evidence/local-verification.json
sh tests/audit.sh bin/asmlab
```

NASM이 설치된 Linux x86-64 환경에서는 다음이 우선 경로이다.

```sh
make clean
make test
```

제작 환경의 문법 변환 검증 경로는 다음과 같이 명시적으로 호출한다. 기본 `make`가 자동으로 이 경로로 우회하지는 않는다.

```sh
make validate-gas
```

이 명령은 `bin/asmlab-validation`을 만든다. NASM에서 생성한 `bin/asmlab`을 덮어쓰지 않는다. 테스트용 Python은 개발 도구이며 애플리케이션 계산 경로에 사용되지 않는다.

## 미검증 또는 미포함 범위

NASM 네이티브 빌드 실행, 원격 CI 실행, 별도 Windows/WSL2 기기, macOS, ARM 및 Raspberry Pi는 이번 실행 검증 대상이 아니다. 수치 함수의 전체 정의역에 대한 올바른 반올림 증명, 전문 CAS 기능, MATLAB 호환성, CPU 간 성능 비교, 광범위한 보안 감사, 멀티스레드 실행 또한 검증하지 않았다.

제공된 GitHub Actions 설정은 후속 네이티브 검증을 실행할 기반이지 이미 통과한 원격 작업의 증거가 아니다. 이 문서의 테스트 통과 횟수를 그 범위 밖의 성공으로 확대하지 않는다.
